Lesson 0004 · Phase 1: Foundations · ~12 minutes

Context as working memory

Tokens, statelessness, and why the window is the whole interface.

Your one win today Explain, in one breath, why an LLM is stateless, why conversations get more expensive every turn, and why “just use a bigger window” is not a memory strategy.

1 · The model has no memory

An LLM is a function: tokens in, tokens out. Every call starts from a blank slate. The feeling of a conversation is a trick the harness plays — it replays the entire transcript on every turn.[1]

Context window The finite sequence of tokens the model can attend to in one call: system prompt, user messages, tool definitions, prior tool calls, observations, retrieved docs. That sequence is the agent's working memory. If it is not in the window, the model does not know it.

Tokens, not words. Providers charge per token, and cap how many you can send. “the cat sat on the” is six integers, not five words.[1] You can see this at OpenAI’s tokenizer.

Because the harness resends the transcript, each extra turn is more expensive than the last: you pay for all previous tokens as input again. Cached prefixes (unchanged bytes at the start of the prompt) are billed cheaper, which is why serious harnesses append-only and never rewrite the prefix.[1]

2 · Context engineering, not prompt poetry

Dex Horthy’s Factor 3: at any moment, the input to the model is “here’s what’s happened so far; what’s the next step?” Everything else is how you pack that sentence.[2]

Context is not only the chat. It is:

  • the system prompt and tool schemas
  • retrieved documents (RAG)
  • prior tool calls and their observations
  • memory pulled in from other sessions
  • instructions about the shape of the next output

The default “messages array” from an SDK is one packing. You can pack better: denser formats, YAML instead of nested JSON, errors compacted, resolved failures dropped. Owning the packing is the difference between a toy loop and a production agent.[2]

Context rot Quality degrades before you hit the hard token cap. As the window fills, recall of any given fact gets worse. Filling a 200k window because you can is how agents get lost. Keep the smallest high-signal set.

3 · When the window fills

Three honest responses, in order of preference:

  1. Don't put it in. Just-in-time retrieval: keep pointers (paths, query ids, URLs) and load bytes only when a tool needs them. Progressive disclosure.
  2. Compact. Summarize older turns into a high-fidelity recap; drop raw tool dumps that have been superseded. This is lossy. Admit that.
  3. Externalize. Write notes to files or a store, and give the agent a tool to read them. That is memory — lesson 0009. It is not “a bigger window.”

Factor 10 is the production corollary: small, focused agents of maybe 3–20 steps, not 100-step monologues. As context grows, models lose the plot. Scope is a context strategy.[3]

Compaction is not the long-horizon store. Anthropic’s managed-agents write-up separates the session log from the window: the log is durable and outside the model; the window is whatever slice you pack for this call.[4] A later session reads the log (or the files in 0017). It does not inherit a compacted transcript by magic.

Interview angle “How do you handle long-running agent conversations?” Weak: “use a 1M context model.” Strong: the model is stateless; the window is working memory; we append-only for cache; we compact or externalize before rot; we keep agents small so they never need the whole history.

4 · Retrieval practice

1. Why does a ten-turn chat cost more than ten times a one-turn chat?

Correct. Stateless function, replayed state. Cached prefixes blunt the bill; they do not remove it.
The model does not remember the last turn. The harness resends everything. Option 2.

2. “Just give it a million-token window” fails as a memory strategy because…

Correct. Context rot. The cap is not the only limit — attention quality is. High-signal, small context wins.
Large windows exist. The problem is quality, not availability. Option 3.

3. Factor 3 in one line: your job each turn is to tell the model…

Correct. That sentence is the whole interface. How you pack it is context engineering.
Dropping history throws away working memory. The packing question is “what happened, what’s next?” Option 1.

4. Which is an honest response to a filling window?

Correct. Compact (lossy, admitted) or externalize (memory-as-a-tool). Temperature is not a memory control.
Silent truncation and temperature are not strategies. Compact or externalize. Option 3.
