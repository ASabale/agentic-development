Lesson 0020 · Phase 5: Career · ~10 minutes

Capstone brief

The portfolio agent you will build in this workspace. Theory first is over; this is the job description.

Your one win today Leave with a scoped capstone you could defend in an interview: framework-free loop, three to seven tools, one HITL seam, a tiny eval set, traces you can show. Not a platform. Not multi-agent.

1 · What “portfolio-grade” means here

From the mission:

A portfolio-grade project in this workspace demonstrating production concerns: guardrails, observability, evals, cost/latency trade-offs, human-in-the-loop.

And: build a non-trivial agent (tools + loop + memory) without a framework, then justify when a framework would be the right call.

Translate that into acceptance criteria you cannot weasel out of:

  • Harness you wrote. The five beats in your language of choice. No LangGraph, no Agents SDK loop until the write-up explains why you would add one.
  • ACI. A handful of tools with real schemas and compact errors. At least one irreversible verb gated by HITL (even if the “human” is you typing y).
  • Memory that is not a slogan. Notes file or sqlite. Pointers in the window. Exact ids stored exactly.
  • Evals. ≥10 tasks with expected world-state. Code graders. One regression run in a README.
  • Traces. Every run dumps the transcript. You can open a fail and talk through it.
  • Write-up. Architecture page that uses this course’s words: workflow vs agent, cost, failure modes, what you would not do.

2 · Pick a small, sharp job

Factor 10. If the demo needs twenty tools, it is two products. Three good options that fit a work machine like this one:

Repo question-answerer

Tools: list_dir, read_file, grep, ask_human. Goal: answer a question about this teaching workspace with citations to files. Eval: 10 questions with known paths.

Ticket triage + draft

Fake a small ticket DB. Tools: search_tickets, get_ticket, search_policy, draft_reply, escalate (HITL). Eval: 10 tickets, expected label + whether escalate fired.

Local research clerk

Tools: web_search (or a fixture corpus), fetch, take_notes, finish. Hard cap 8 steps. Eval: 10 queries with must-cite URLs or fixture ids.

Do not build a platform. Do not spawn subagents. Do not fine-tune. Those are out of mission scope or Phase-4 luxuries you have not earned on a resume with a missing loop.

3 · Order of build

The shapes to copy — directory, one eval row, one tool schema, the trace line, the README headings — are on the capstone kit. Build in this order:

  1. Write the eval tasks first (0013). Empty array of cases. This is the contract.
  2. Write the tool schemas and a dumb fake backend (0005, 0011).
  3. Write the loop (0002). Make eval 1 pass with canned tool results if you must.
  4. Add error compaction and a step cap (Factor 9, 10).
  5. Add HITL on the dangerous verb (0012).
  6. Add notes memory (0009).
  7. Measure tokens per task. Put the number in the write-up.
  8. Only then talk about a framework you would have used for pause/resume (0016).
How you will talk about it “I wrote a tools-in-a-loop harness without a framework, with X tools, a human gate on Y, and N eval tasks grading world-state. Token cost is Z per task. I would reach for LangGraph if I needed durable interrupts across processes. I did not, yet.”

4 · Retrieval practice

1. First artifact of the capstone, before a clever loop?

Correct. Evals first. The tasks are the spec. Diagrams and runtimes come after a loop that can fail those tasks.
No subagents, no framework-first. Tasks with expected state. Option 1.

2. Why HITL still appears in a solo portfolio project?

Correct. The seam is the production concern. A stdin confirm counts. Slack can wait.
Not a vendor requirement, not an API rule. Show the interrupt. Option 3.

3. A capstone that only demos a happy path is weak because…

Correct. Mission language: guardrails, observability, evals, cost, HITL. The happy path is table stakes.
Traces can record anything, and the loop is still the definition. Show the production surface. Option 2.

4. Out of scope for this capstone?

Correct. Mission out-of-scope: weights-level work. Phase 4 multi-agent is a luxury until the loop exists.
Notes and evals are in scope. Fine-tune + swarm is not. Option 3.
