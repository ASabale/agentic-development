Lesson 0017 · Phase 4: Advanced · ~12 minutes

Long-running harnesses

Sessions forget. Artifacts remember. Compaction is not a handoff.

Your one win today Explain why a bigger window does not make a week-long agent, and name Anthropic’s two-agent pattern: an initializer that scaffolds, a coding agent that leaves clean artifacts for the next shift.

1 · The problem is the shift change

A single LLM call has a window. A “session” is one such window, maybe compacted. A project lasts days. Each new session begins amnesiac. Anthropic’s Effective harnesses for long-running agents compares this to engineers on shifts: the next person needs the repo, the notes, and a way to see that the tests were green when you left.[1]

Two failure modes they name:

  • The agent tries to one-shot the entire job in one window, then drown.
  • The agent declares victory early so it can stop emitting tokens.

Compaction (lesson 0004) is lossy summary inside a session. It does not replace a handoff across sessions. If the next call cannot git log and read a progress file, it will redo or undo the last shift.

2 · Initializer + coding agent

Anthropic’s two-fold solution:[1]

Initializer (first run)

Scaffold the environment. Write a machine-readable feature list (feature_list.json — JSON, not markdown, because it resists poetic corruption). Write init.sh. Leave a clean baseline.

Coding agent (every later session)

Make incremental progress. Leave artifacts: progress notes, descriptive git history, passing tests. Stop before the window turns to mush.

A session protocol you can steal:

  1. Read the progress file.
  2. Read the feature list. Pick the highest-priority incomplete item.
  3. Read recent git log (~20 commits) as the true history.
  4. Start the server / run the baseline tests. Do not work on a red tree.
  5. Implement the one item. Verify. Commit with a message a future session can parse.
  6. Write notes for the next shift. Exit.

That is Factor 5 (unify state — the repo is the state), Factor 6 (pause/resume), Factor 10 (small steps), Factor 12 (the next process is a reducer over those artifacts). It is also just good engineering, which is the joke and the point.

Interview angle “How would you run an agent overnight on a repo?” Weak: “1M context.” Strong: initializer + per-session worker; externalized feature list and git as memory; verify before and after; compaction only within a session; eval on ‘did the next session know what happened.’ Mention a fresh-context evaluator so the grader does not share the builder’s delusions.

3 · Retrieval practice

1. Why doesn’t a huge context window solve week-long work?

Correct. Amnesia at session start, rot inside a session. Artifacts bridge shifts. Git can be a tool.
Not padding, and git is a fine tool. Sessions forget; files don't. Option 2.

2. JSON for the feature list, not markdown, because…

Correct. Anthropic’s stated reason: JSON resists corruption better than a free-form progress novel.
They can write markdown, and token price is not the reason. Structure is. Option 3.

3. Compaction vs handoff artifacts?

Correct. Different timescales. Do not ask a summary to be a repo.
Not the same, and git is an artifact, not compaction. Option 1.

4. A coding session should end when…

Correct. Incremental progress. One-shotting and early victory are the named failure modes.
Don't one-shot, don't empty the window for fun. Finish one verified item. Option 3.
