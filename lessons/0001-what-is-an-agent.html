What is an agent?

Lesson 0001 · Phase 1: Foundations · ~10 minutes

Your one win today State the consensus definition from memory, name the augmented LLM as the block an agent is built from, and classify any system as agent or workflow.

1 · The one-sentence definition

Consensus definition An LLM agent runs tools in a loop to achieve a goal. [Willison 2025]

That sentence compressed two years of industry argument into one line.[1] Unpack it word by word, because every later phase of this course hangs off one of these terms:

  • An LLM — a large language model (Claude, GPT, Gemini…). The brain. It produces text; more precisely, it produces a decision about what to do next.
  • Tools — functions your code can execute: search the web, read a file, call an API, run SQL. The model cannot touch the world directly; it can only ask for a tool to be run. Tools are the hands.
  • In a loop — the model's request is executed, the result is shown back to the model, and the model decides what happens next. This cycle — decide → act → observe → decide — repeats. The loop is the habit.
  • To achieve a goal — the loop has a stopping condition. Agents are not infinite loops: they run until the model believes the job is done.[1] The goal is the job description.
Mental model Agent = brain + hands + habit + job description. An LLM, given tools, run in a loop, until a goal is met.

Everything else in this field — memory, planning, guardrails, multi-agent systems, evaluation — is a variation or an upgrade on one of those four parts.

2 · Agent vs. workflow — the line that matters

Anthropic makes a clean distinction that the industry has converged on:[3]

Workflow LLMs and tools orchestrated through predefined code paths. Your code decides the order of steps.
Agent The LLM dynamically directs its own process and tool usage — your code maintains the loop, but the model chooses the path.

The test is one question: who is picking the next step — the programmer, or the model? A pipeline that runs summarize → translate → email in a fixed order is a workflow, even if every step uses an LLM. A bot that reads a support ticket, decides to look up the account, decides whether to issue a refund, and then drafts a reply is an agent, because the model chose those steps at runtime.

This distinction is not pedantry — it is a cost/reliability trade-off. Anthropic's first advice: find the simplest solution possible, and only increase complexity when it demonstrably helps.[3] Agents trade your control flow for the model's flexibility, and you pay for it in latency, cost, and failure modes. Practitioners who have shipped agents emphasize that many problems people reach for an agent to solve were scripts all along.[4]

Interview angle "How would you decide whether a use case needs an agent?" The strong answer: default to a workflow; reach for an agent only when the task's steps can't be enumerated in advance — when the path depends on what you discover along the way. Name the cost: agents burn tokens, latency, and reliability for that flexibility.[4]

3 · The augmented LLM

Anthropic’s building block, one step below the loop, is the augmented LLM: the same model call, with retrieval, tools, and memory attached.[3] A single augmented call is not yet an agent. Your code still decides that this call happens, then that one. The agent is what you get when you put that block in a loop and let the model pick the next tool.

Augmented LLM One model call plus the extras it can use on that call: tools, retrieved text, memory. The loop — who chooses the next call — is a separate decision, taught in lesson 0002.

Interviews that open on “draw an agent” want this picture first: model in the middle, tools and retrieval around it, then an arrow back into the model labeled “observation.” If you only say “it uses tools,” you have skipped the block the 2024 post is organized around.

It's about control flow, not model count or team size: workflows follow code you wrote; the agent's model picks the path. Option 2.

3. Complete the field's consensus definition: an LLM agent…

Correct — Willison's line: "runs tools in a loop to achieve a goal." Note "a goal": the stopping condition is part of the definition.
Say it raw: tools, loop, goal. An agent "runs tools inside a loop to achieve one goal" — retries aren't the point, and one-tool-per-loop is a limitation nobody imposed.
