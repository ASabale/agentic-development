Lesson 0014 · Phase 3: Production · ~14 minutes

Twelve-factor agents

Own your prompts, your window, and your control flow. The rest is commentary.

Your one win today Recite the twelve factors as a production checklist, and compress them into three ownership claims you can defend on a whiteboard.

1 · Why this list exists

Dex Horthy wrote 12-Factor Agents after shipping, after trying the frameworks, after watching founders who were doing well mostly not use those frameworks. The uncomfortable observation: products billed as agents are often mostly deterministic software with LLM steps at the magical points. The list is the engineering that makes that mix reliable.[1]

It is opinion, not a spec. It rhymes with Anthropic (“start with the API; patterns are a few lines of code”) and with LangGraph’s pitch (the loop is easy; durable execution is not). Use it as a review checklist, not as scripture.

2 · The twelve

Print the one-pager. What follows is the memory palace — three ownership claims, four factors each.

Own the tokens

  1. Natural language → tool calls. The atomic trick: a sentence becomes structured intent. Deterministic code takes it from there.
  2. Own your prompts. If a framework hides the prompt, you cannot debug or eval. The string is your source code.
  3. Own your context window. “Here’s what happened; what’s next?” Pack it yourself (lesson 0004).
  4. Tools are structured outputs. JSON in; your switch decides (lesson 0011).

Own the lifetime

  1. Unify execution state and business state. One event log, not a conversation object plus a ticket object that drift.
  2. Launch / pause / resume with simple APIs. Agents must sleep. Serialize the thread, wake on a webhook.
  3. Contact humans with tool calls. HITL is an intent (lesson 0012).
  4. Own your control flow. The while is yours: which intents continue, which break, which wait for approval before invocation.

Own the failure

  1. Compact errors into the window. Self-heal with a short observation; cap retries; then escalate.
  2. Small, focused agents. 3–20 steps. As context grows, models get lost. Grow scope only as evals allow.
  3. Trigger from anywhere. Slack, email, cron, webhook. The agent is a service, not a chat box.
  4. Make the agent a stateless reducer. next = reduce(events). State lives outside the process. This is Factor 12 “mostly for fun,” and also how you survive a restart.
Whiteboard compression Own tokens. Own lifetime. Own failure. If a design violates one of those, it will hurt in production even if the demo was pretty.
Interview angle “Would you use LangChain?” Translate to 12-factor. If the framework lets you own prompts, context, and the pause-before-invoke seam, it may pay (lesson 0016). If it hides those, you are renting a demo. Horthy’s founders were rolling the stack themselves.

3 · Retrieval practice

1. The three ownership claims that compress the twelve?

Correct. Tokens (1–4), lifetime (5–8), failure (9–12). Weights-level work is out of this course’s scope.
Not training, not branding. Ownership of tokens, lifetime, failure. Option 2.

2. Factor 10 exists because…

Correct. Context rot, lesson 0004. Small agents are a context strategy, not a fashion.
No legal cap, no framework crash. The limit is attention. Option 3.

3. “Stateless reducer” means…

Correct. The step function is pure-ish; state is the event log you persist. Restarts become cheap.
Not tool-less, not log-less. State lives outside the process. Option 1.

4. Horthy’s empirical nudge toward this list was that…

Correct. LLM steps at the magical points, deterministic code everywhere else. Design for that mix.
No ban, and production is not 100-step autonomy. Mostly software. Option 3.
