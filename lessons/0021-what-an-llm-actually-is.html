Lesson 0021 · Phase 1 depth · ~12 minutes

What an LLM actually is

A next-token engine. Not a database, not an agent, not a mind. The substrate under every later lesson.

Your one win today Explain, without mysticism, what happens in one API call: tokens in, a distribution over the next token, sample, repeat. Then name three things that are not in that picture (memory, tools, truth).

1 · Completion is the only primitive

Willison’s teaching version is the right altitude:[1] a Large Language Model completes a sequence. Give it “the cat sat on the ” and it almost certainly continues “mat.” Modern models complete more interesting prefixes — a function, a plan, a JSON object that happens to look like a tool call.

They do not work in words. Text is mapped to integer tokens (subword pieces). “the cat sat on the ” is six integers, not five words. You can watch this at OpenAI’s tokenizer. Billing, rate limits, and the context window are all in these integers.

One forward pass The model reads the whole current token sequence, produces a probability distribution over the next token, a sampler picks one (greedy, temperature, top-p), that token is appended, and the process repeats until a stop token or a token cap. That is generation. Everything branded “chat” or “agent” is this loop plus your code.

2 · Chat is a costume on completion

Early models were raw completion engines. Chat models wrap the same engine in a chat template: reserved markers for system, user, assistant, and now tool-call blocks. Under the template it is still “complete this string.”[1]

The model is stateless. It does not remember the last HTTP request. The harness resends the transcript every time (lesson 0004). “Memory,” “tools,” and “personality” are not weights doing extra jobs. They are tokens you chose to put in the prefix, plus code you run when the completion looks like a function call.

3 · Three things people smuggle in

SloganWhat is actually true
“The model knows our wiki.”Only if the wiki (or a chunk of it) is in the window this call, or was in the training data — which is stale, uncited, and not a permission boundary.
“The model decided to refund.”It emitted JSON. Your harness refunded, or did not (lessons 0002, 0011).
“The model is thinking.”It is sampling tokens that look like reasoning. Useful (CoT, lesson 0006). Not a separate faculty with access to extra facts.

This is why agent design is mostly context engineering and harness design, not model-whispering. You cannot give the model a new sense. You can give it tokens and tools.

Interview angle “What is an LLM, really?” Weak: “it’s like a brain.” Strong: next-token model over a finite window; chat/tools are a template and a parser; state lives in the harness; truth is not a sampling feature. Then pivot to why that makes the five-beat loop inevitable.

4 · Retrieval practice

1. The only primitive an LLM API gives you is…

Correct. Tokens in, tokens out. Sessions, tools, and memory are your code around that primitive.
No durable session in the weights, no RPC on their GPU (client tools). Completion. Option 2.

2. A chat transcript feels like memory because…

Correct. Lesson 0004. Stateless function, replayed window. That is the trick.
No hidden session tensor, no per-turn fine-tune. Replay. Option 3.

3. “The model knows it is 14°C in Paris” is true only if…

Correct. No flag, no telemetry. In the window this call, or maybe in the weights — which is not a product feature.
Dashboards and parameter counts do not fetch weather. Option 1.

4. Why this lesson sits under agents, not under ML theory?

Correct. Mission out-of-scope: transformer internals. In-scope: do not mystify the brain. Design the loop.
You don't need backprop, and temperature is not ACI. Agents = completion + harness. Option 3.
