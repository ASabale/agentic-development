Lesson 0012 · Phase 3: Production · ~12 minutes

Guardrails and human-in-the-loop

Layered defense around the loop. A human is a tool that pauses it.

Your one win today Name a layered guardrail stack, and model human contact as a tool call that breaks the loop until a webhook resumes it — not as a vibe of “someone will watch.”

1 · Guardrails are around the model, not inside it

OpenAI’s Practical Guide to Building Agents treats an agent as a system that can halt and transfer control when it fails or hits a high-risk action. Guardrails are a layered defense, not a longer system prompt.[1]

LayerJob
Relevance classifierKeep the run on-scope. Off-topic → refuse or reroute.
Safety classifierJailbreaks, disallowed content, prompt injection in observations.
PII / moderation filtersStrip or block sensitive data in or out.
Tool safeguardsRate each tool’s blast radius. Read-only vs. money-moving vs. irreversible.
Rules-based checksBlocklists, regex, length caps, allowlisted ids. Cheap and deterministic.
Output validationSchema, policy, groundedness against retrieved evidence.
EscalationOn failure or high risk, stop. Do not hope the next thought will behave.

Willison’s least-favorite “agent” definition is staff replacement. Accountability stays with a human. A computer can never be held accountable; therefore a computer must never make a management decision — the 1979 IBM slide still wins.[2]

Anthropic’s production advice matches: checkpoints for human oversight on high-stakes actions; keep planning steps transparent so a reviewer can see the path.[3]

2 · Humans are a tool

12-factor Factor 7: do not special-case “ask the user” as leftover chat. Give the model a request_human_input intent — question, context, urgency, format (yes/no, multiple choice, free text). When that intent fires:[4]

  1. Append the request to state.
  2. Persist the thread (you are about to go to sleep).
  3. Notify a human on Slack, email, a ticket — Factor 11, meet them where they are.
  4. Break the loop. Do not while sleep in a request worker.
  5. A webhook arrives with the answer; you load state, append the observation, resume.

That is Factor 6 (launch / pause / resume) and Factor 8 (own control flow) in one motion. The number-one missing feature Dex asks of every framework: interrupt between tool selection and tool invocation, so a human can approve the call before it runs.[5] Without that seam you either (a) block in memory, (b) restrict the agent to toys, or (c) yolo production writes.

HITL, operationally An explicit control-flow state. Not a dashboard someone might glance at. High-risk intents pause; low-risk intents run; repeated failures escalate. The policy is code.
Interview angle “How do you keep a refund agent safe?” Weak: “we’ll prompt it to be careful.” Strong: tool-risk ratings; refund is pause-and-approve; relevance/safety classifiers on the ticket and on tool observations (injection arrives through tools); output caps; a human tool; evals on a red-team set. Name the IBM slide if they push “full autonomy.”

3 · Retrieval practice

1. The right place for a jailbreak defense is…

Correct. Guardrails are around the model. Prompts are one weak layer, not the stack.
Models disobey. Embeddings are not a safety layer. Put code around the loop. Option 2.

2. Factor 7 models a human as…

Correct. request_human_input is structured output. Persistence is mandatory; in-memory sleep is not.
Ambient review is not a control-flow state. The human is a tool with pause/resume. Option 3.

3. Why interrupt between selection and invocation?

Correct. Dex’s framework feature request. Without the seam, you yolo or you never ship writes.
You cannot un-run a refund. Billing is irrelevant. Option 1.

4. “Replace the finance team with an agent” fails first on…

Correct. Willison: agency and accountability stay human. Tools-in-a-loop is not a staff replacement.
Cost and schema are real issues; the category error is accountability. Option 3.
