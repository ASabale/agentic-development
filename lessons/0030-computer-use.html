Lesson 0030 · Phase 4 depth · ~10 minutes

Computer use

Screenshots in, mouse events out. Still the five beats. A much larger ACI.

Your one win today Map computer-use onto lesson 0002: the model never drives the OS; it emits actions or a script; your environment executes and returns a screenshot. Then name why this ACI is high-risk.

1 · Same loop, visual observations

OpenAI’s computer-use guide: you provide the environment and execute the model’s requests. The model uses screenshots and other tool results to decide what to do next.[1] Two shapes they now document:

Computer tool

Structured actions: click, type, scroll, screenshot, … Your harness maps them onto Playwright or OS events. One action (or a short batch) per beat.

Code execution

A function tool that accepts a script (PyAutoGUI, Playwright). One call can loop. Still your sandbox; still your screenshot back to the model. Recommended on their newest models.

Multimodal tokens (lesson 0021) are how a screenshot enters the window: images become tokens, same as text. They are expensive and they rot like anything else. Keep the same browser/VM session across calls so the model is not staring at a fresh boot every beat.[1]

Still not an agent product Computer use is an ACI: a way to ground actions in a GUI when no API exists. You still need a goal, a stop, HITL on anything that can spend or send, and a sandbox that cannot see prod credentials. Willison’s “ChatGPT agent” (a branded browser) is this pattern, and it is still tools-in-a-loop. [2]

2 · Why the blast radius jumps

  • The tool surface is “whatever the GUI can do,” which is the opposite of a poka-yoke schema (0005).
  • Injection now includes pixels: on-screen text is an observation (0027).
  • Screenshots are huge observations — context rot (0004) arrives in three turns.
  • You need a real sandbox (browser profile, VM). This is where “the API does not execute” is life-or-death.

Prefer an API tool if one exists. Computer use is the residue — the vendor with no API, the one flow you must click. Cap steps. Watch traces as video-of-spans, not as hope.

Interview angle “Should we let the agent drive the admin UI?” Strong: only if no API; sandbox; screenshot budget; HITL on submit; treat on-screen copy as untrusted. Weak: “vision models are good now, so yes.”

3 · Retrieval practice

1. Who moves the mouse?

Correct. Same split as 0002. You provide the environment. They sample tokens.
No USB, and they do not host your desktop unless you built that. Option 2.

2. Computer use vs a refund(order_id) tool?

Correct. Prefer the narrow API. Computer use is residual surface area.
Modals are not a harness. Pixels vs JSON is not “identical safety.” Option 3.

3. Screenshots belong in the window as…

Correct. Vision tokens in the same prefix. Budget them. Willison: not a separate OCR pipeline in the usual case.
Usually not a hidden OCR model, and the model *can* see the image tokens. Option 1.

4. First extra control vs a normal tool loop?

Correct. Execution environment is the product. Prod-connected computer use is a nightmare ACI.
Keep HITL; keep prod away. Sandbox. Option 3.
