Inner vs outer loop

Chat is one trigger. Production agents start from cron, Slack, and tickets. Factor 11.

Your one win today Draw two sequences: Human→Agent (inner) and Agent→Human (outer). Own the second as a paused thread plus a webhook, not as a chatbot that never sleeps.

1 · Who speaks first

Inner loop

A human is sitting there. Each user message runs the five beats until an answer. ChatGPT, a support widget, Claude Code in the terminal. The process can be long-lived because someone is waiting.

Outer loop

A cron, a Stripe event, a Jira webhook starts the agent. The agent may contact a human (Factor 7) and go to sleep for hours. Control flow is Agent→Human, then resume. Dex’s “outer loop agents.”[1]

Factor 11: trigger from anywhere, meet users where they are.[2] If your only interface is a chat box, you have a demo. Production tickets arrive as JSON.

2 · Why the harness changes

Inner loop can cheat: hold the transcript in RAM, input() for HITL, process stays up. Outer loop cannot:

  • Serialize the thread (Factor 5/6) before you return 200 to the webhook.
  • Idempotency. The same Stripe event may fire twice. reduce(events) must not double-refund.
  • Timeouts. “Waiting for Alex” is a state, not a 30-second HTTP request.
  • AuthZ of the trigger. A public webhook is a new injection and fraud surface (0027).

The seven-move interview script (0018) should start with “how does this job start?” If the answer is only “the user types,” push: overnight, email, failed CI — that is the outer loop, and it is where pause/resume earns a runtime (0016).

Interview angle “Design a deploy bot for Slack.” Strong: Slack message is a trigger; thread is persisted; list_tags is inner-loop-fast; deploy_prod is outer — request_human_input, persist, resume on reaction. Weak: “a ChatGPT window that an intern pastes into.”

1. Outer loop means…

Correct. Trigger from anywhere. Thoughts and subagents are orthogonal.
Not leftover CoT, not nested agents. Events vs a waiting human. Option 2.

Correct. Webhooks retry. reduce(events) is how you survive that.
TCP doesn't save you, and cache ≠ idempotency. Option 1.

Not Slack-only, and outer loop *does* speak first. Option 3.
