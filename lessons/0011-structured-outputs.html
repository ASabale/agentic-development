Lesson 0011 · Phase 3: Production · ~10 minutes

Structured outputs

A tool call is JSON your code decides how to run. Schema-valid is not truth.

Your one win today Distinguish JSON mode from Structured Outputs, and treat every tool call as structured intent — not a remote procedure the model is allowed to invoke.

1 · Tools are just structured outputs

12-factor Factor 4, in one sentence: asking a model to “use a tool” is asking it to emit JSON you can parse into an object. Deterministic code then does something with that object. The model does not get a file descriptor.[1]

class CreateIssue:
    intent: "create_issue"
    title: str
    team_id: str

# model emits JSON matching that shape
# your switch statement decides whether — and how — to call Jira

That switch is the whole point. You may refuse. You may ask a human. You may remap fields. You may no-op. “The model called create_issue” is not “Jira now contains an issue.” Factor 8 (own your control flow) is this switch statement grown up.[2]

2 · JSON mode is not a schema

Three rungs, easy to mash in interviews:[3]

RungGuaranteesDoes not guarantee
Prompt “reply in JSON”NothingValid JSON, or the right keys
JSON modeThe output is valid JSON (with listed edge cases)That it matches your schema
Structured Outputs (strict: true / json_schema)The output matches the supplied JSON SchemaThat the values are true, safe, or wise

OpenAI: Structured Outputs “ensures the model will always generate responses that adhere to your supplied JSON Schema.” Unlike JSON mode, it constrains shape, not only validity.[3] It still cannot stop a schema-valid refund of the wrong order. Constraints are syntactic. Semantics stay your problem — with evals (0013) and guardrails (0012).

Handle the remaining holes: refusals, truncated outputs at token limits, unsupported schema features in strict mode. Production code never json.loads blindly.

Interview angle “How do you make tool calls reliable?” Strong: schema as contract, Structured Outputs / strict decoding for shape, a harness switch that can refuse or interrupt, compact errors on parse failure, never equate valid JSON with a correct action.

3 · Retrieval practice

1. Factor 4’s punchline is that a tool call is…

Correct. JSON in, deterministic code out — or not. The model never held the credential.
The model cannot syscall, and the provider does not run your function (client tools). Option 3.

2. JSON mode vs Structured Outputs?

Correct. Shape vs mere validity. Cite OpenAI's Structured Outputs guide if asked.
Do not reverse them, and they are not the same flag. Option 1.

3. A strict-schema refund call for order_id=999 (the wrong order) is…

Correct. Syntax ≠ truth. Guardrails and HITL exist for this row of the table.
Strict mode does not query your DB. Valid can be wrong. Option 2.

4. Why own the switch on intent rather than auto-dispatch?

Correct. That flexibility is Factor 4 meeting Factor 8. Auto-dispatch is how agents “just yolo” high-stakes tools.
Nothing about parsers or keys forces a switch. Control flow does. Option 3.
