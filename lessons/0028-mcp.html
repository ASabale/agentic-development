Lesson 0028 · Phase 4 depth · ~12 minutes

Model Context Protocol

A USB-C for tools, resources, and prompts. Not an agent. Not a replacement for your harness.

Your one win today Draw host / client / server, name the three server primitives (tools, resources, prompts), and say what MCP explicitly does not decide — how you loop, how you pack context.

1 · What it is

MCP is an open protocol for connecting AI applications to external systems. The docs’ own metaphor: USB-C for AI apps.[1] Anthropic pointed at it in Building effective agents as one way to expose a well-documented tool interface to the model.[2]

Participants:[3]

  • Host — the AI app (Claude Desktop, VS Code, your harness).
  • Client — one connection object inside the host, per server.
  • Server — a process that exposes context. Local via stdio, or remote via Streamable HTTP.

Two layers: a JSON-RPC data layer (what you can list and call) and a transport layer (stdio vs HTTP). You will almost always talk to an SDK, not to raw JSON-RPC. Know the nouns anyway.

MCP does not run your agent The spec’s own note: MCP focuses on context exchange. It does not dictate how the application uses LLMs or manages the provided context. Your loop, your window, your HITL — still lessons 0002, 0004, 0012.

2 · Three primitives servers expose

PrimitiveControlled byJob
ToolsThe model (with optional human approval)Actions: tools/list, tools/call. This is your ACI, standardized.
ResourcesThe application / userReadable context (files, schemas, records). Pointers you might fetch just-in-time (0004, 0009).
PromptsThe user / UIReusable templates the client can surface (slash commands). Factor 2 still says: you must be able to see the rendered string.

That split is the design lesson. Not everything should be a tool. A database schema is a resource. “Write a commit message given this diff” is a prompt template. “Run the query” is a tool — and a risky one.

Security is not free with the USB-C metaphor. A local filesystem server is a large ACI. Treat MCP servers with the same least-privilege and injection stance as any other tool (0027). Official docs have a security section for a reason.

Interview angle “Would you use MCP?” Strong: as a standard ACI bus when several hosts must share tools; I still own the loop and the prompt; resources vs tools vs prompts is the useful taxonomy; I would not wrap every SQL as an MCP tool. Weak: “MCP is how you build agents now.”

3 · Retrieval practice

1. MCP, compressed?

Correct. USB-C. The loop is still yours. The model is still someone else's API.
Not a runtime, not a model. Protocol. Option 3.

2. Host vs server?

Correct. VS Code is a host; it instantiates a client per server (Sentry, filesystem, …).
Not GPUs, not synonyms. App vs context process. Option 1.

3. A database schema should usually be an MCP…

Correct. Resources are data. Tools are actions. Mixing them is how ACIs get noisy and unsafe.
Don't force a per-turn tool call, and schemas aren't few-shot. Resource. Option 2.

4. Why MCP does not retire Factor 2 and 8?

Correct. Quoted from the architecture page. USB-C does not drive the car.
It doesn't steal your prompt. It also doesn't run your while loop. Option 3.
