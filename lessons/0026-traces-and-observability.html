Lesson 0026 · Phase 3 depth · ~12 minutes

Traces and observability

If you cannot open a failed run and see every beat, you do not have an agent you can ship.

Your one win today Name the span tree of one agent run (invoke → model call → execute_tool × N → final), and list the fields you’d put on each span so a grader bug and a hijack are distinguishable.

1 · A run is a trace, not a log line

OpenTelemetry’s generative-AI semantic conventions (still evolving, already useful) treat an agent invocation as a span with children:[1]

  • invoke_agent — the whole job
  • nested chat / generate spans — each model call, with token counts
  • nested execute_tool — each harness execution, with name and (redacted) args
  • optional invoke_workflow if you can tell several agents were coordinated

Vendors (LangSmith, etc.) will ingest OTel. The point is not the brand. The point is: one trace id for the ticket, every beat attached, you can click a fail from eval 0013 and read it — the same instinct as Anthropic’s “audit the grader.”[2]

Minimum viable trace run_id, parent/child spans, model, prompt hash (not the full secret prompt in the UI if you can’t), tool name, call_id, latency, input/output/cached token counts, stop reason, error. Redact PII and secrets in args. Keep the full transcript in a store your on-call can open.

2 · What traces are for

QuestionYou need
Did we call the refund tool?execute_tool span, name, args, whether HITL approved
Why was this slow?TTFT vs generation vs tool wall time, per span
Why was this expensive?input / cached / output tokens per model call (0023, 0025)
Did the grader lie?The transcript the grader saw, side by side with the score
Was this injection?The observation that preceded the weird tool call, intact

Print debugging is not this. A 40-step run in stdout is how you lose the p95. Structure first; pretty UI later.

Interview angle “How do you observe agents?” Weak: “CloudWatch logs.” Strong: one trace per job, OTel gen_ai names if we can, token accounting, tool spans, redaction, eval failures deep-link to traces. Without that we cannot do 0013.

3 · Retrieval practice

1. The parent span of an agent job should be…

Correct. One job, one tree. Unstitched tool traces cannot explain a hijack.
Not per-token spam, not disconnected tools. Nested tree. Option 2.

2. Why hash the prompt on the span instead of dumping it always?

Correct. Factor 2 wants the string in git. Traces want a handle plus a locked-down store for the full text.
Not a spec requirement, and prompts are text. Privacy + eval diffs. Option 3.

3. An eval fail with no trace is…

Correct. Anthropic: read transcripts. A score without a trace is a rumor.
Scores without traces are how grader bugs live for months. Option 1.

4. Token fields on a generate span exist so you can…

Correct. 0023’s envelope becomes empirical per intent. Cache hits belong here too.
Not a training set, not an anti-cache rule. Per-step cost. Option 3.
