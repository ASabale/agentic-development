Workflow patterns

Anthropic, Building effective agents. All five are workflows: your code owns the topology.

PatternWhat happensWhenWatch for
Prompt chaining LLM calls in a fixed sequence; gates between steps. Task cleanly splits into known subtasks. Latency stacks. A bad intermediate poisons the rest if you skip gates.
Routing Classify, then send to a specialist prompt or model. Distinct categories; classification is reliable. Misroutes. Optimizing one branch must not wreck others.
Parallelization Sectioning: independent subtasks at once. Voting: same task, many attempts, aggregate. Speed, or confidence from multiple looks. Cost × N. Voting needs an aggregator you trust.
Orchestrator–workers Lead model invents subtasks at runtime, delegates, synthesizes. You cannot pre-list the subtasks (e.g. which files to edit). Looks like multi-agent. Still a workflow: you wrote the shape. Token-heavy.
Evaluator–optimizer Generate → critique against criteria → revise, loop. Criteria are clear; feedback actually improves the next draft. Infinite polish. Cap the loop. Weak criteria waste spend.
Then the agent Drop the fixed graph. The model picks tools in a loop until a goal is met. Use only when the path depends on what you discover. You pay in latency, cost, and failure modes.

The building block under all of the above is the augmented LLM (retrieval + tools + memory). Climb the ladder only when a lower rung’s eval says you must.
