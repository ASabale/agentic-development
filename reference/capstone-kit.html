Capstone kit

The files, shapes, and order for the portfolio agent in lesson 0020. Copy the shapes. Write the code yourself. One job, one harness, no framework.

1 · Done means this

  • A loop you wrote: send context, model emits a tool call, your code runs it, you append the observation by id, stop on a final answer or a step cap.
  • Three to seven tools. Schemas are real. Errors are short strings the model can read.
  • One irreversible tool that pauses for a human before it runs. A yes/no on stdin counts.
  • Memory outside the window: a notes file or sqlite. The model reads and writes it with tools.
  • At least ten eval tasks. A grader checks world-state or a citation, not “the prose looked fine.”
  • Every run writes a trace you can open.
  • A README that states the job, the token cost of one passing task, one failure you traced, and when you would add a framework.

2 · Layout

capstone/
  README.md
  evals/tasks.jsonl
  evals/grade.py
  tools.py          # schemas + handlers
  loop.py           # the five beats
  traces/           # one jsonl per run
  memory/notes.md

Put this in its own directory. Do not bury it inside the lesson HTML.

3 · Eval row (write these first)

One JSON object per line. Ten lines before you call a model.

{"id": "q1",
 "input": "Which file defines the agent loop beats?",
 "expect": {"cites": ["lessons/0002-tools-in-a-loop.html"],
            "must_not_call": ["delete_file"]}}

The grader reads the trace. Pass if every path in cites appears in a tool result the model actually received, and no forbidden tool ran. For the ticket job, expect is {"label": "billing", "escalated": false} and the grader checks the database, not the sentence.

4 · One tool

{"name": "read_file",
 "description": "Return the text of a file under the workspace. Path is relative. Refuses paths outside the root.",
 "parameters": {"type": "object",
   "properties": {"path": {"type": "string"}},
   "required": ["path"],
   "additionalProperties": false}}

The handler returns either the text or one line: error: path escapes root. Do not return a stack trace.

5 · The loop, in the order the course uses

  1. Load the system prompt and the user task. Append nothing else yet.
  2. Call the model with the tool list. If the message has no tool call, that is the final answer. Stop.
  3. If the tool is on the irreversible list, print the arguments and wait for y. n appends error: human rejected and continues. Do not run the handler first.
  4. Else run the handler. Append the observation with the tool-call id.
  5. If steps exceed 8, stop and record capped. Factor 10: a bigger cap is a different product.

Parallel calls and tool_choice can wait. A correct serial loop is the portfolio.

6 · Trace line

{"step": 2, "kind": "tool", "name": "read_file",
 "args": {"path": "lessons/0002-tools-in-a-loop.html"},
 "ok": true, "chars": 4200}

Also record kind: "model" with input and output token counts when the API returns them. The README number is the sum for one task, not a guess.

7 · README headings

  1. Job in one sentence, and why it is an agent rather than a workflow.
  2. Tools, and which one pauses.
  3. Eval: how many tasks, what the grader checks, last pass count.
  4. Cost: tokens (and, if you have it, dollars) for one passing task and one failure.
  5. One traced failure: what the model did, what you changed.
  6. Framework: the concrete feature you do not have yet (durable pause across processes is the usual honest answer). Do not add it to pass the README.

8 · Pick one job

JobToolsGrader looks at
Repo question-answererlist_dir, read_file, grep, ask_humancited paths that were actually read
Ticket triagesearch_tickets, get_ticket, search_policy, draft_reply, escalatelabel, and whether escalate paused
Research clerksearch, fetch, take_notes, finishmust-cite ids; step count ≤ 8

A fourth job is fine if it still fits section 1. Twenty tools, a fine-tune, or a swarm of agents does not.
